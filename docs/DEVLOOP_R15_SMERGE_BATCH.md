# Φ DevLoop R15: Owner Smerge Batch (Agentora documentation only)

**Status: draft, no live merge qualification.** This is a narrow browser-first convenience layer on the already merged DevLoop R0. It does not create a new task orchestrator, a standing agent grant, an autonomous coder, or a cross-repository merge token.

## The problem

The owner handles many GitHub PRs, but individually opening and merging them is exhausting. Existing DevLoop R0 supports a docs-only `phi-automerge` label on **Agentora**. Autonomous R1 can independently create/merge one exact-edit task after a real owner environment approval, but R9–R14 do not authorize code publication or cross-repository auto-merge.

R15 reduces **repeat clicks only after one explicit owner action**. It deliberately does not enable unattended merges, general patches, other repositories, or automatic approval of anything. Documentation-only PRs are the first qualification lane.

## Browser-only operator path

1. In GitHub, review each candidate's **Files changed** and exact 40-character **head commit SHA**. Do not select a PR containing code, CI, workflow, secrets, release, policy or dependency changes.
2. Open [R15 Owner Smerge Batch](../.github/workflows/devloop-r15-smerge-batch.yml) from **Agentora → Actions** after it is *manually reviewed and merged as infrastructure*. Select `main`.
3. Use `mode=preview`, `pr_heads=31@<FULL_40_HEX>,32@<FULL_40_HEX>`. At most five explicit PR/SHA entries. Read the workflow Summary and `r15-smerge-preview-RUN_ID` JSON artifact. This sends **GET only**, with read-only token permissions.
4. If and only if every candidate is READY, choose `mode=merge` with the exact same PR/SHA entries and type **`SMERGE_AGENTORA_DOCS_EXACT_SHA`**. This one owner-authorized workflow attempts ordinary GitHub squash merges; it never bypasses required checks or branch rules. It refuses reruns.
5. Inspect `r15-smerge-merge-RUN_ID` artifact for **MERGED_GITHUB_READBACK**, explicit HOLD, or partial outcome. If a GitHub response is uncertain, inspect the actual PR; never blindly retry or assume a failure means no merge.

The merge action is **not** activated by opening, approving, editing, or merging this infrastructure PR. No schedule, PR event, webhook or issue automatically triggers batch merges. It may remain disabled simply by never invoking merge mode.

## Hard gates

- `workflow_dispatch` only, on `main`, in exact Agentora repository ID `1167870912`, actor/login numeric identity `247459237`, first run attempt, original GitHub event sender and repo identity.
- Explicit exact `PR_NUMBER@HEAD_SHA` with 40 lowercase hex characters; unique IDs, maximum five, and a separate confirmation only in `merge` mode.
- PR must be OPEN, not draft, **authored by MichaelWave369**, same-repo branch to Agentora `main`, mergeable, no hold/conflicting auto-merge labels, and have 1–10 complete added/modified `README.md` or `docs/**/*.md` files only.
- No non-Markdown files, workflows, security/dependency/CI config, executable code, renamed/deleted files, forks or AI-supplied merge labels. The exact workflow input itself is the one-time owner's review/approval; it is **not** generated by a bot or permanent.
- Require active Agentora main ruleset with required checks via the existing `devloop_automerge.protected` gate, actual three required Actions checks on exact SHA, no other non-success/ambiguous check runs and no failing legacy commit status contexts.
- Analyze **every candidate before any merge**. One initial HOLD aborts all writes. Before each subsequent effect, re-fetch PR, base SHA, changed-file metadata and checks/rules, and ensure they match the approved snapshot. GitHub normal SHA-pinned merge endpoint has final authority.
- Read back the resulting GitHub PR and merge SHA; return `MERGED_GITHUB_READBACK` separately from CI success. A late failure can leave a partial batch; the retained receipt explicitly marks remaining items NOT_ATTEMPTED. Never retry a complete workflow run using old approval.
- Neither preview nor merge modifies PR labels, GitHub settings, protected rules, Actions variables, branch protection, release, deployment, approval state or private inventory.

## Readiness and integration

**This solves only one slice of the owner's merging burden:** Agentora docs PRs. It does NOT implement standing grants for 275 repositories, autonomous code-writing, QA impersonation, unattended PR selection or cross-repo authentication.

The **auto PR/merge/loop** north star remains [Fleet issue #124](https://github.com/MichaelWave369/Agentora/issues/124): RepoNerve observation → R12 GitHub-native Issue mission → approved bounded Autonomous R1 worker → separate App PR publisher → verified exact-head CI → independent QA → trusted merge gate → PhiMada readback. R15 is a focused operator convenience lane and should not become a second policy authority. The existing DevLoop policy and Autonomous R1 code remain unchanged.

**First acceptance:** dry-run on one real *new* owner-authored docs-only Agentora PR, then separately authorize one true merge field trial. This draft changes a privileged workflow, so manually review the source and test evidence. **Do not merge R15 via its own label or use it to merge its own infrastructure PR.**

Ledger Above Ego. One permission for one exact job, never unlimited authority.
